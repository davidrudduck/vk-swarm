## Refuted hypotheses (recorded so a later round does not re-open them)

- **`usize` underflow from an out-of-range dependency index.** Refuted twice over. Ordering is correct (`breakdown.rs:227` precedes `:234`; `queries.rs:136-149` precedes `:153`). Stronger: underflow is impossible *regardless* of ordering — an index `j >= len` is never popped (the queue only holds `0..len`), so it inflates the counter rather than decrementing past zero. This also proves a distinct-count fix stays underflow-safe.
- **Double accept creating duplicate child tasks.** `accept_proposal` re-reads on the tx handle and rejects non-`Draft` at `queries.rs:318`, and writes `accepted` via raw SQL at `:427`, bypassing `update_status`. The permissive `(a, b) if a == b` arm cannot reach it.
- **Stray `InProgress` write on the breakdown path.** Only executor-start write is `container.rs:1503`, behind the predicate. `should_finalize` false for `Breakdown` (`container.rs:260-264`); `mark_process_failed_with_task_update` matches only `CodingAgent | SetupScript | CleanupScript` (`:589-593`); DevServer behaviour bit-for-bit unchanged. The other live write, `approvals.rs:345`, is gated on `InReview`, unreachable from a breakdown run.
- **MCP typed-`Uuid` breaking the tool schema.** `schemars` carries `uuid1`, so the schema advertises `{"type":"string","format":"uuid"}` — strictly more precise. Structs are `Deserialize`-only; no serialisation path changed.
- **`item_to_task` lookup masking an invariant violation.** The first pass inserts an entry for every element of `items` and `item.id` is a primary key, so `.get()` cannot fail. Dead defensive code, strictly safer than the panicking index it replaced.
- **The migration silently altering `v_workstream_state`.** Verified independently twice: the `CREATE VIEW` block in `20260809000000` is identical to `20260201000200` — same 13 projected columns, order, aliases, joins and predicates. No other migration mentions the view.
- **Accept transaction not atomic.** One `tx`, all four writes on it (child `INSERT INTO tasks`, `node_outbox` `task.upsert`, every `task_dependencies` edge, the status flip), one `commit()`. Every `?` and early return precedes the commit; dropping `tx` rolls back.
- **Outbox rows missing for children.** One per child, byte-identical in shape to `Task::enqueue_task_upsert_op`. `shared_task_id: None` is back-filled by the periodic sweeper (`hive_sync.rs:319-322`), so this is not a repeat of the dangling-shared_task_id finding.
- **Origin-node guard missing on an entry path.** Present on all three — all funnel through `create_draft_proposal` (`breakdown.rs:56`), which rejects `project.is_remote` at `:68-73`. REST → `:178`; auto-on-create → `core.rs:310`; retry → `:223`. The MCP tools are pure HTTP proxies and inherit it.
- **Route/handler wiring mismatch.** All six routes mounted and one-to-one with `frontend/src/lib/api/breakdown.ts`; no orphans either side.
- **Detached run corrupting a closed pool.** Not a corruption path — a write to a closed pool returns `Err`, which `breakdown.rs:94-106` converts to a Failed proposal. The real issue is the swallowed panic (finding 7).
- **Compose project pinned on every invocation / trap reaching a foreign stack / volume-name collision.** All confirmed sound. Every compose call routes through `dc()`; no raw `docker compose` survives; unknown-arg `exit 1` precedes trap arming; the preflight sets `SKIP_DOCKER=true` before aborting; `COMPOSE_ENV_ARGS` eliminates the missing-env-file case; e2e and production volume names cannot collide. The residual hazards are findings 2 and 3, not these.
