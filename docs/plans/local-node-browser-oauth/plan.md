# local-node-browser-oauth Plan

## Spec
docs/superpowers/specs/2026-08-21-local-node-browser-oauth.md

## Approach
Add an additive local authorization layer around the EXISTING Hive OAuth exchange, in dependency order: durable state first, then the HTTP boundary, then protocol and revocation coverage, then the frontend and deployed evidence. 22 tasks across 4 phases.

Decisions locked before execution, so no task has to re-derive them:
- **Endpoints.** `GET /api/auth/state` is a NEW public route on a new `routes/browser_auth.rs`; it returns only `{authorized, oauth_available}`. The existing `GET /api/auth/status` is NOT repurposed — it keeps its daemon-profile meaning and simply becomes protected. Browser sign-out is a NEW `POST /api/auth/browser/logout`; the existing `POST /api/auth/logout` keeps its name and its disconnect semantics (revoke all sessions, stop sync, remove daemon credentials). Keeping that name is a REVERSIBLE backward-compatibility choice grounded in a real caller: `frontend/src/lib/api/oauth.ts` already binds `oauthApi.logout()` to that path with disconnect meaning, so adding the browser-scoped action under a new path leaves every existing caller correct, whereas a rename would silently change what an unmigrated caller does. D5 requires only that the two operations be separately NAMED. A later workstream can rename it to `/auth/disconnect` with a one-line route change plus the caller update.
- **Cookies.** `vks_browser_session` (`HttpOnly; SameSite=Lax; Path=/; Max-Age=157680000`, no `Secure`, per D9) and `vks_browser_binding` (`HttpOnly; SameSite=Lax; Path=/; Max-Age=600`). `SameSite=Lax` on the binding cookie is load-bearing: the Hive callback is a cross-site top-level GET navigation, and `Strict` would withhold the cookie and make every rightful login look like a wrong-browser rejection. Cookies are parsed and emitted by a ~10-line helper module; no cookie crate and no `axum-extra` feature change.
- **Persistence.** Three additive tables, INTEGER unix-epoch-millisecond timestamps bound explicitly from an injected clock (never a SQL DEFAULT — see the event_journal collation regression), BLOB UUIDs, lowercase-hex SHA-256 hashes as TEXT, runtime-checked sqlx query forms only (`.sqlx` has no cache for the new tables), and `db::test_utils::create_test_pool()` everywhere. No hand-written test schema.
- **Routing: four explicit groups, not three (D1/D7).** `public_routes` contains health, OAuth init/complete and auth-state. `protected_routes` contains every browser-only API and stream behind `require_browser_session`. `connection_stream_routes` is behind `require_session_or_connection_token` and contains exactly the three production direct-stream registrations that receive Hive `connection` credentials: `/api/logs/{execution_id}/live`, `/api/execution-processes/{id}/raw-logs/ws`, and `/api/task-attempts/{id}/diff/ws`. The frontend proves the diff classification: `useDiffStream.ts:113-139` builds that exact attempt-id URL with `?token=<connection_token>`, while no production caller uses `/api/task-attempts/by-task-id/{task_id}/diff/ws`; the latter stays browser-session-only. `node_to_node_routes` is behind `require_session_or_proxy_token` and contains the by-remote-id and by-task-id HTTP proxy subtrees, explicitly excluding the by-task-id diff WebSocket. The two alternative-credential layers are separate: `connection` never opens proxy HTTP, `node_proxy` never opens direct logs or diffs, and no shared predicate accepts both. Missing, malformed, wrong-audience, wrong-target-node, absent-resource or wrong-resource credentials return 401 before lookup or upgrade. Connection tokens require this node plus `Some(exact path resource)`; proxy tokens require this target node. Unknown `/api/*` terminates on the API router's own fallback instead of falling through to SPA HTML.
- **Protocol testing is real.** The harness speaks actual WebSocket (tokio-tungstenite `connect_async`, valid `Sec-WebSocket-Key`) and actual SSE (`Accept: text/event-stream`, body never consumed). A deliberately malformed handshake is not a protocol test: it cannot observe a 101 and so cannot distinguish an authentication rejection from an upgrade refusal. Task 013 censuses all ten current WS/SSE routes from the real routers.
- **Ordering at the callback.** claim plus capture of the shared browser-auth epoch (one short critical section) -> redeem -> fetch profile with the CANDIDATE token -> pin-or-verify owner -> re-check the epoch under the same guard -> save credentials -> mint session -> synchronously install sync. Explicit disconnect increments the epoch and durably invalidates pending handoffs before revoking sessions. A callback linearized before disconnect either commits first and is revoked, or fails its commit re-check; a callback after disconnect cannot claim a pre-disconnect handoff. A rejected subject writes nothing and revokes nothing.
- **The verifier is TDD too.** `scripts/verify-local-node-browser-oauth.sh` (the spec's `verify_cmd`) ships with `scripts/test-verify-local-node-browser-oauth.sh`, which stands up throwaway `node -e` HTTP fixtures and proves the verifier PASSES a compliant node and FAILS an open one, an SPA-fallback one and a token-leaking one. A checker that never fails certifies nothing.
- **Deliberate non-removals.** `LocalDeployment::store_oauth_handoff` / `take_oauth_handoff` and `oauthApi.logout`'s definition remain in the tree, unused. Deleting code a previous author wrote is the rubric's irreversible class and is out of scope here; their call sites are removed and `forbid_after` enforces that for `oauthApi.logout`.
- **Green throughout.** Task 006 repoints all seven pre-existing served-router test files through an authorized cookie jar BEFORE the boundary lands (a behaviour-preserving change while the API is still open), so `cargo test -p server` never goes red between tasks. Task 008 additionally inverts the one `harness_smoke.rs` assertion that encodes the old SPA-fallback behaviour.

Coverage ownership: SC1->008, SC2->013, SC3/SC4->010, SC5/SC6->011, SC7/SC8->012, SC9->015, SC10->018; TS1->004, TS2->011, TS3->014, TS4->015, TS5->016, TS6->018, TS7->021. Tasks 001-003, 005-007, 009, 013, 017, 019 and 020 carry supportive checks without claiming test coverage beyond any separately listed success criterion.


## Phases
- **Phase 1: Durable local authorization core** — Land the irreversible additive migration, the deterministic clock/token/hash seams, and hash-only owner, handoff and session models whose expiry, single-consumption and revocation semantics are proven with an injected clock on migrated test pools.
- **Phase 2: Served HTTP boundary and browser-bound OAuth** — Make the served-router harness cookie-aware, split the node router into explicit public and protected subtrees with an API-terminating fallback and a minimal public auth-state endpoint, and turn the existing Hive handoff into a browser-bound flow that identifies the candidate and pins the owner BEFORE saving daemon credentials or minting a session.
- **Phase 3: Protocol coverage, revocation scope and outage continuity** — Authenticate every WebSocket and SSE stream before upgrade, give hive direct-log/diff streams and node-to-node proxy routes an explicit alternative credential with no anonymous fallback, separate browser logout from Hive disconnect, and prove that restart and Hive outages leave established sessions and local work intact.
- **Phase 4: Frontend boundary, non-disclosure and deployed acceptance** — Gate the SPA on public auth state with a central 401 teardown and visibly distinct sign-out and disconnect actions, prove with sentinel credentials that no Hive token is browser-visible, ship the deployed verifier and the trusted-LAN operator document, and close on a real non-loopback acceptance run with every repository gate green.
