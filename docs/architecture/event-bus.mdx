The node's event system delivers task-lifecycle changes to SSE clients (the live board) and
internal trigger hooks, with durability and gapless resume. The full design rationale is
**ADR-0017** (`dev-docs/adr/0017-durable-event-journal-bus.md`); this page is the working map.

## Data flow

```text
model write (Task::create / update_status / delete, attempt lifecycle)
    │  same transaction
    ▼
event_journal::append  →  event_journal table (monotonic seq)
    │
    ▼
journal tailer (polls for new rows)
    │
    ▼
EventBus (tokio broadcast)
    ├─► GET /api/events (SSE, cursor resume)
    └─► trigger-hook runner (persisted trigger_cursors)
```

The journal append happens **in the same transaction** as the model write — an event exists if and
only if the state change committed. Everything downstream (tailer, bus, SSE, hooks) is a reader of
that durable log, so a crash at any point loses no events that are still within retained history:
consumers resume from their cursor, and compaction (below) bounds how far back that history goes.

## Event types

`NodeEvent` (`crates/db/src/models/event.rs`) covers the task lifecycle:
`TaskCreated`, `TaskStatusChanged`, `TaskDeleted`, `AttemptStarted`, `AttemptFinished`,
`AttemptFailed`. Each journal row carries a monotonically increasing `seq` — the resume token for
every consumer.

## SSE endpoint

`GET /api/events` (`crates/server/src/routes/events.rs`):

- **No `cursor` param** → live-only from now. This is deliberately distinct from `cursor=0`.
- **`cursor=N`** → `EventBus::subscribe_from(N)` replays every journaled event with `seq > N`,
  then continues live on the same connection.
- Every SSE frame carries its `seq` as the SSE `id`, so clients resume with
  `?cursor=<last-seen-seq>` after a disconnect. Duplicates are tolerated. Within retained
  history, replay is gapless; a cursor older than the compaction window (see below) is rejected
  with **410 Gone** before the stream starts — the explicit signal that compaction deleted events
  the client never saw, so it must refresh its state and reconnect without a cursor. A cursor at
  exactly `low_water - 1` still resumes gaplessly at the first retained row.
- A setup failure (journal unreachable) is an HTTP error; a **mid-stream** failure emits one
  terminal `event: error` frame and ends the stream — never a silent close.
- A malformed `cursor` is a 400 from axum's `Query` extractor.

## Trigger-hook seam

Internal consumers run through the trigger runner with a persisted cursor per hook
(`trigger_cursors` table: `hook_name`, `last_processed_seq`, `needs_rebootstrap`). A hook that
crashes resumes from its cursor. If compaction's hard cap deleted rows past a hook's cursor, the
hook is flagged `needs_rebootstrap` and must rebuild from current state rather than replay.

## Compaction

`event_compaction.rs` runs on an interval (default 60s) applying, in order: the retention window
(`VK_EVENT_RETENTION_HOURS`), the row floor (`VK_EVENT_MIN_ROWS`), the trigger-cursor floor, and
finally the hard cap (`VK_EVENT_MAX_ROWS`, which overrides the cursor floor and flags affected
consumers). Config values are sanitised before every run (floor of 1, `max >= min`) — see
[Event Journal Retention](/configuration-customisation/event-journal-retention) for the admin view.

## Startup wiring

`LocalDeployment::from_parts` (`crates/local-deployment/src/lib.rs`) constructs the bus and spawns
the tailer, trigger runner, and compaction loop; handlers reach the bus via the inherent accessor
`deployment.event_bus()` (the `Deployment` trait is unchanged — `DeploymentImpl` is the concrete
type).

## Tests

- `crates/server/tests/events.rs` — SSE integration suite: live-only vs replay, seq on every
  frame, gapless reconnect, real-seam test driving `Task::create` end to end
  (`sse_delivers_an_event_from_a_real_task_write`), and fault-injected terminal error frame.
- `crates/services` — bus/tailer/compaction unit + colocated tests (env parsing, clamping,
  cursor floor, hard-cap rebootstrap).
- `crates/db` — journal model tests (append/list/compact, offline coverage).

## Offline behaviour

The entire pipeline is node-local: journal, bus, SSE, and hooks all function with the hive
unreachable. Hive sync consumes the same model state independently.
